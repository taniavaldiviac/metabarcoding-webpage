Dada2 - Dereplicación e Inferencia de Errores

Este paso tiene dos partes: primero dereplicamos las lecturas (eliminamos duplicados y contamos abundancias), luego aprendemos el modelo de error de la secuenciadora para poder distinguir errores técnicos de variantes biológicas reales.

Paso 1 — Dereplicación

¿Qué es la dereplicación?

Después del filtrado, cada muestra tiene miles de lecturas — pero muchas de ellas son idénticas entre sí. La dereplicación agrupa todas las lecturas con exactamente la misma secuencia en una sola entrada, y registra cuántas veces apareció cada una (su abundancia).

Por ejemplo, si una muestra tiene 200,000 lecturas pero solo 15,000 secuencias únicas, la dereplicación reduce el volumen de datos de 200,000 a 15,000 entradas, cada una con su conteo de abundancia. Esto hace que los pasos siguientes (modelado de errores, inferencia de ASVs) sean mucho más rápidos sin perder ninguna información biológica.

Código 
exists <- file.exists(filtFs) & file.exists(filtRs)
filtFs <- filtFs[exists]
filtRs <- filtRs[exists]
sample.names <- sample.names[exists]

derepFs <- derepFastq(filtFs, verbose = TRUE)
derepRs <- derepFastq(filtRs, verbose = TRUE)
names(derepFs) <- sample.names
names(derepRs) <- sample.names

Diagnóstico de la dereplicación

Revisamos los resultados de la primera muestra para entender qué obtenemos:

  • Top 5 abundancias: la secuencia más abundante apareció 70,868 veces. Estas secuencias dominantes probablemente corresponden a las especies de peces más comunes en la muestra
  • El ratio de compresión del 7.63% indica diversidad moderada, lo cual es típico en muestras de eDNA marinas

Paso 2 — Aprender el modelo de error

¿Por qué necesitamos un modelo de error?

La secuenciadora Illumina comete errores al leer las bases — una A real puede leerse como C, G o T. Estos errores no son aleatorios: dependen del tipo de transición (A→C es más frecuente que A→T) y de la calidad Phred de cada posición. Si no corregimos estos errores, los confundiríamos con variantes biológicas reales y sobreestimaríamos la diversidad de nuestra muestra.

learnErrors() estima las tasas de error específicas de tu run de secuenciación. Esto es importante porque cada corrida tiene un perfil de error ligeramente diferente — depende del estado del equipo, los reactivos, la densidad del cluster, etc. Por eso DADA2 no usa tasas genéricas, sino que las aprende directamente de tus datos.

Preparación: definir parámetros y validar datos

Antes de lanzar learnErrors(), el pipeline define los parámetros de entrenamiento y verifica que haya suficientes datos para construir un modelo confiable:

Código 
nbases_target <- 1e8   # 100 millones de bases (aumentar si tienes > 50 muestras)
max_consist   <- 25    # más iteraciones que el default (10) para forzar convergencia

# Validar datos disponibles
total_bases_F <- sum(sapply(filtFs, function(f) if (file.exists(f)) file.info(f)$size else 0))
total_bases_R <- sum(sapply(filtRs, function(r) if (file.exists(r)) file.info(r)$size else 0))
message("Forward disponible: ~", round(total_bases_F / 1e6, 1), " MB")
message("Reverse disponible: ~", round(total_bases_R / 1e6, 1), " MB")

if (total_bases_F < 1e6 || total_bases_R < 1e6)
  warning("Datos muy limitados (< 1 MB). El modelo puede ser inestable.")

En nuestros datos, la salida se ve así:

Forward disponible: ~95.2 MB
Reverse disponible: ~96.1 MB

¿Qué nos dicen estos números? Los ~95 MB por dirección representan el tamaño total de los archivos FASTQ filtrados. Esto es una estimación indirecta de cuántas bases tenemos disponibles — como regla general, un archivo FASTQ de 95 MB contiene aproximadamente 100–150 millones de bases (cada base ocupa ~1 byte de secuencia más metadatos de calidad y encabezados). Con 95 MB tenemos datos más que suficientes para alcanzar nuestro objetivo de nbases_target = 1e8 (100 millones de bases).

Nota

¿Cuándo preocuparte? Si ves valores menores a 1 MB, el pipeline lanza una advertencia porque no habrá suficientes bases para estimar las 12 tasas de error con precisión. Esto puede pasar cuando muchas muestras fueron descartadas en el filtrado, o cuando trabajas con un subconjunto muy pequeño de datos. En ese caso, reduce nbases_target (por ejemplo a 1e7) para que DADA2 no intente usar más datos de los que existen.

Parámetros clave

Los parámetros que controlan el aprendizaje del modelo son:

Parámetro Valor Qué hace
nbases 1e8 (100M) Número de bases a usar para aprender el modelo. DADA2 toma tantas muestras como necesite para alcanzar ese total. Aumentar a 2e8 si tienes > 50 muestras
randomize TRUE Selecciona lecturas al azar en lugar de tomar siempre las primeras. Produce un modelo más representativo
multithread 2 Número de núcleos a usar. Con ~30 personas en el servidor, usamos 2 para no saturarlo
MAX_CONSIST 25 Número máximo de iteraciones del algoritmo. El default de DADA2 es 10; aquí se aumenta a 25 para garantizar convergencia
Código 
errF <- tryCatch({
  learnErrors(filtFs, nbases = nbases_target, randomize = TRUE,
              multithread = 2, MAX_CONSIST = max_consist, verbose = TRUE)
}, error = function(e) {
  stop("Error al aprender modelo Forward: ", conditionMessage(e))
})

errR <- tryCatch({
  learnErrors(filtRs, nbases = nbases_target, randomize = TRUE,
              multithread = 2, MAX_CONSIST = max_consist, verbose = TRUE)
}, error = function(e) {
  stop("Error al aprender modelo Reverse: ", conditionMessage(e))
})

¿Cómo leer esta salida?

Cada bloque corresponde a una dirección (Forward primero, Reverse después). Desglosemos la primera línea:

103156235 total bases in 1587019 reads from 12 samples — DADA2 necesitaba 100 millones de bases (nbases_target = 1e8) y encontró 103 millones en 1.59 millones de lecturas, tomadas de 12 de nuestras muestras. No necesitó usar todas las muestras porque alcanzó el objetivo con 12. Para Reverse, necesitó 13 muestras para llegar a 105 millones — esto es normal porque las lecturas Reverse pueden tener longitudes ligeramente distintas después del filtrado.

Initializing error rates to maximum possible estimate — El algoritmo comienza asumiendo el peor escenario: que todas las diferencias entre lecturas son errores. A partir de ahí, va refinando.

selfConsist step 1 ............ — Los puntos representan las muestras que se procesan en cada iteración. En el step 1 aparecen 12 puntos (uno por muestra usada en Forward).

¿Qué significa “convergencia”?

learnErrors() trabaja de forma iterativa — en cada ronda:

  1. Estima las tasas de error con los datos actuales
  2. Infiere ASVs preliminares usando esas tasas
  3. Re-estima los errores separando las variantes reales de los errores

Cuando las estimaciones dejan de cambiar significativamente entre rondas, el modelo convergió — es decir, encontró tasas de error estables que explican bien los patrones en tus datos.

En nuestro caso: Forward convergió en 10 rondas y Reverse en 9 rondas. Ambos están en el rango ideal.

Rondas Interpretación
3–5 Convergencia muy rápida — datos de excelente calidad o poca complejidad
5–15 Rango típico — el modelo se ajustó bien
15–25 Convergencia lenta — datos complejos o ruidosos, pero el modelo es válido
No converge (alcanza MAX_CONSIST) Problema: aumenta MAX_CONSIST a 50 o revisa la calidad de tus datos
Tip

¿Por qué Reverse convergió más rápido que Forward? No siempre es así. A veces Reverse tarda más porque tiene mayor tasa de error, pero en nuestros datos la diferencia es mínima (10 vs 9 rondas). Lo importante es que ambos convergieron dentro del límite de MAX_CONSIST = 25.

Validación automática del modelo

Después de aprender los modelos, el pipeline valida que las tasas de error estimadas sean razonables. ¿Por qué es necesario? Porque learnErrors() siempre produce un resultado — incluso con datos malos — pero eso no garantiza que el modelo sea confiable. La validación revisa la matriz de errores (err_out) que contiene las tasas estimadas para cada tipo de transición en cada nivel de calidad.

¿Qué es err_out? Es una matriz de 16 filas × 41 columnas:

  • 16 filas = todas las combinaciones posibles de base real → base leída (A2A, A2C, A2G, A2T, C2A, C2C, …, T2T)
  • 41 columnas = los Q-scores de 0 a 40

Cada celda contiene la probabilidad estimada de esa transición en ese nivel de calidad. Por ejemplo, la celda [A2C, Q30] dice “la probabilidad de que una A real se lea como C cuando la calidad es Q30”.

Código 
# Validar modelo Forward
if (!is.null(errF$err_out)) {
  rn         <- rownames(errF$err_out)
  error_rows <- rn[substr(rn, 1, 1) != substr(rn, 3, 3)]   # A2C, A2G, etc.
  q_cols     <- as.integer(colnames(errF$err_out))
  hq_cols    <- which(q_cols >= 20)                          # columnas Q≥20

  err_hq  <- errF$err_out[error_rows, hq_cols, drop = FALSE]
  max_err <- max(err_hq, na.rm = TRUE)

  message("Tipos de transición de error: ", length(error_rows), " (de 16 posibles)")
  message("Tasa de error máxima en Q≥20: ", round(max_err, 5),
          " (normal si < 0.05; preocupante si > 0.10)")

  if (max_err > 0.1)
    warning("Tasa de error > 10% en Q≥20. Revisa el perfil de calidad del run.")
  else
    message("Modelo de error OK.")
}

¿Qué hace este código paso a paso?

  1. Filtra las transiciones de error — De las 16 filas, excluye las 4 diagonales (A2A, C2C, G2G, T2T) porque representan lecturas correctas, no errores. Quedan 12 transiciones de error reales (A2C, A2G, A2T, C2A, C2G, etc.)

  2. Selecciona solo calidades Q≥20 — Las bases con Q < 20 ya fueron eliminadas en el filtrado (filterAndTrim), así que las tasas de error en calidades bajas no son relevantes para nuestros datos. Evaluar solo Q≥20 evita alarmas falsas por tasas altas en bins de calidad que no usamos

  3. Calcula la tasa máxima — Busca el peor caso entre todas las transiciones de error en calidades altas. Si esa tasa máxima es < 5%, el modelo es confiable. Si supera el 10%, algo anda mal

Tasa máxima en Q≥20 Interpretación
< 0.01 (1%) Excelente — tasas de error muy bajas en calidades altas
0.01–0.05 (1–5%) Normal — rango típico para datos de Illumina
0.05–0.10 (5–10%) Aceptable pero marginal — revisa los gráficos de error
> 0.10 (>10%) Problemático — una base de alta calidad tiene >10% de probabilidad de ser un error. Revisa la calidad del run o el filtrado
Nota

¿Por qué 12 transiciones y no 16? Hay 4 bases (A, C, G, T) y cada una puede leerse como cualquiera de las 4, dando 4×4 = 16 combinaciones. Pero 4 de ellas son la base leyéndose correctamente (A→A, C→C, G→G, T→T). Estas tienen probabilidades cercanas a 1.0 y no representan errores, por eso se excluyen de la validación.

Paso 3 — Visualizar el modelo de error

El gráfico de errores muestra las 12 posibles transiciones (A->C, A->G, etc.). Los puntos rojos son las tasas observadas; la linea negra es el modelo ajustado. Deben seguir el mismo patrón: la tasa de error cae conforme aumenta la calidad (Q-score).

Código 
plotErrors(errF, nominalQ = TRUE)
plotErrors(errR, nominalQ = TRUE)

Al ejecutar estas líneas verás advertencias como estas:

Warning messages:
1: In scale_y_log10() :
  log-10 transformation introduced infinite values.
2: Removed 164 rows containing missing values or values outside the scale range (`geom_line()`).
3: Removed 164 rows containing missing values or values outside the scale range (`geom_line()`).

Estas advertencias son normales y no indican un problema. Ocurren porque:

  • log-10 transformation introduced infinite values — Algunas transiciones tienen tasa de error = 0 (cero errores observados en ciertos bins de calidad). El logaritmo de 0 es −∞, y ggplot simplemente omite esos puntos del gráfico. Esto es esperado, especialmente en calidades altas donde ciertos tipos de error son extremadamente raros.

  • Removed 164 rows containing missing values — Consecuencia de lo anterior: los 164 puntos con valores infinitos o ausentes se excluyen de las líneas del gráfico. El número exacto varía según tus datos, pero valores entre 100 y 300 son típicos. Que aparezca el mismo mensaje dos veces es porque plotErrors() dibuja dos capas de líneas (el modelo ajustado y la tasa nominal).

Tip

Regla práctica: si plotErrors() produce una gráfica visible con el patrón esperado (tasas decrecientes), las advertencias de scale_y_log10 se pueden ignorar con confianza. Solo preocúpate si la gráfica aparece vacía o si las líneas no se dibujan en absoluto.

El pipeline guarda estas gráficas automáticamente en final_data/logs/:

Cómo leer esta gráfica

La gráfica tiene 16 paneles organizados en una cuadrícula de 4×4. Cada panel representa una transición entre bases — la fila indica la base real y la columna la base leída por la secuenciadora:

Tip

Cómo leer las gráficas:

  • Los puntos grises son las tasas de error observadas en tus datos, agrupadas por Q-score. El tamaño del punto indica cuántas bases hay en ese bin — puntos grandes = muchos datos (estimación confiable), puntos pequeños = pocos datos (más incertidumbre)
  • La línea negra es el modelo de error ajustado por DADA2 — lo que aprendió learnErrors(). Esta es la curva que DADA2 usará para corregir errores en el paso dada()
  • La línea roja es la tasa de error teórica según la definición nominal del Q-score (Q20 = 1 error en 100 bases, Q30 = 1 en 1,000, Q40 = 1 en 10,000)
  • El eje X (Consensus quality score) va de 0 a 40 — a mayor Q-score, mayor confianza en la base
  • El eje Y (Error frequency) está en escala logarítmica — cada marca representa un cambio de 100×. Esto permite ver tanto errores frecuentes (1e-01 = 10%) como errores raros (1e-05 = 0.001%)

Los dos tipos de paneles

Diagonal (A2A, C2C, G2G, T2T): la base real y la leída son la misma — representan lecturas correctas. Nota que en nuestra gráfica estos paneles aparecen vacíos o con muy pocos puntos. Esto es normal: plotErrors() grafica la frecuencia de error, y una lectura correcta no es un error, así que la frecuencia es cercana a 0 (o exactamente 0, lo que genera los valores infinitos en log10 que vimos en las advertencias).

Fuera de la diagonal (A2C, A2G, C2A, T2G, etc.): errores reales — la secuenciadora leyó una base distinta a la real. Aquí es donde debemos fijarnos. En cada panel:

  • La tasa de error debe bajar de izquierda a derecha — a mayor calidad Phred, menos errores
  • La línea negra debe seguir los puntos grises — esto significa que el modelo se ajustó bien a los datos observados
  • La línea negra no tiene que coincidir con la línea roja — la roja asume un modelo ideal de Illumina, pero cada run tiene su propio perfil de error real

¿Qué vemos en nuestros datos?

Mirando los paneles de error (fuera de la diagonal):

  • Tendencia decreciente clara: en todos los paneles (A2C, A2G, G2A, T2C, etc.) la tasa de error baja conforme aumenta el Q-score. Por ejemplo, en G2A la tasa cae de ~1e-02 (1%) en Q10 a ~1e-04 (0.01%) en Q35. Esto es exactamente lo que esperamos
  • La línea negra sigue los puntos grises: el modelo captura bien el patrón de los datos observados. No hay paneles donde la línea se desvíe sistemáticamente de los puntos
  • Puntos grandes en Q bajos: los puntos más grandes están en calidades bajas (Q < 15), donde se concentran más datos de error. A calidades altas los puntos son más pequeños porque hay menos errores que contar
  • Ondulaciones en la línea negra: en algunos paneles (como T2C o A2T) la línea negra tiene pequeños “brincos” en calidades intermedias. Esto es normal cuando hay pocos reads en esos bins de Q — no indica un problema si el patrón general sigue siendo decreciente
  • La línea negra está por encima de la línea roja en Q altos: en varios paneles (A2C, A2T, C2T, T2C) las tasas observadas son ligeramente mayores que las teóricas en calidades altas. Esto es típico — la definición nominal del Q-score es optimista, y el perfil real de cada run difiere. Precisamente por eso DADA2 aprende su propio modelo en lugar de usar las tasas teóricas
Nota

¿Debo comparar Forward vs Reverse? Sí. Es normal que la gráfica Reverse tenga tasas de error ligeramente más altas (puntos grises más arriba), especialmente en Q altos. Si Reverse se ve dramáticamente peor (línea negra plana, puntos muy dispersos), considera un truncamiento más agresivo con truncLen en filterAndTrim.

Paso 5 — Inferencia de ASVs con dada()

¿Qué hace este paso?

Este es el paso central de DADA2 — donde ocurre la “magia”. La función dada() toma las secuencias dereplicadas y el modelo de error que acabamos de aprender, y determina cuáles secuencias únicas son variantes biológicas reales (ASVs) y cuáles son errores de secuenciación.

El algoritmo funciona así para cada muestra:

  1. Toma todas las secuencias únicas y sus abundancias (del paso de dereplicación)
  2. Compara cada secuencia con las más abundantes usando el modelo de error
  3. Si la diferencia entre dos secuencias es consistente con un error de secuenciación (según las tasas aprendidas), las agrupa — la menos abundante se considera un error de la más abundante
  4. Si la diferencia no puede explicarse por errores de secuenciación, las mantiene separadas — son ASVs distintas

El resultado es un conjunto de ASVs por muestra: secuencias biológicas reales, corregidas de errores, a resolución de nucleótido único.

Ejecutar la inferencia

Código 
dadaFs <- dada(derepFs, err = errF, multithread = 2)
dadaRs <- dada(derepRs, err = errR, multithread = 2)

Al finalizar verás para cada muestra un resumen como este:

Sample 1 - 228534 reads in 17428 unique sequences.
Sample 2 - 175230 reads in 14302 unique sequences.
...

Explorar los resultados

Código 
# Resumen de la primera muestra
dadaFs[[1]]

La salida te muestra cuántas ASVs se infirieron de cuántas secuencias únicas. Por ejemplo:

126 sequence variants were inferred from 17428 input unique sequences.

Esto significa que de las 17,428 secuencias únicas que tenía la muestra 1 después de la dereplicación, DADA2 determinó que solo 126 son variantes biológicas reales. Las otras ~17,300 son errores de secuenciación de esas 126.

¿Cómo interpretar el número de ASVs?

Secuencias únicas ASVs inferidas Ratio Interpretación
17,428 126 0.7% Típico — la mayoría de las secuencias únicas son errores
5,000 200 4% Mayor proporción de variantes reales — posible alta diversidad
20,000 20 0.1% Muy pocas ASVs — muestra dominada por pocas especies
10,000 5,000 50% Inusual — revisa el modelo de error o la calidad del filtrado
Nota

¿Por qué tan pocas ASVs? En eDNA de peces con el marcador 12S, es normal obtener entre 50 y 200 ASVs por muestra. La mayoría de las secuencias únicas en la dereplicación son variantes con 1-2 bases de diferencia respecto a una ASV abundante — exactamente el tipo de error que el modelo de learnErrors() aprendió a reconocer. El denoising las “colapsa” de vuelta a la secuencia original.

NotaRecuerda
  • learnErrors() necesita suficientes datos (al menos varios MB de FASTQ filtrados) para estimar tasas confiables.
  • Si el modelo no converge, aumenta MAX_CONSIST a 50 o nbases_target a 2e8.
  • Los modelos errF y errR son independientes: las lecturas Reverse suelen tener tasas de error ligeramente mayores que las Forward, y eso es normal.
