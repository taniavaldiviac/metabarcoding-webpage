Dada2 - Dereplicación e Inferencia de Errores

Este paso tiene dos partes: primero dereplicamos las lecturas (eliminamos duplicados y contamos abundancias), luego aprendemos el modelo de error de la secuenciadora para poder distinguir errores técnicos de variantes biológicas reales.

Paso 1 — Dereplicación

La dereplicación colapsa lecturas identicas en secuencias únicas y registra cuantas veces aparece cada una. Esto reduce el volumen de datos sin perder información biológica.

Código 
exists <- file.exists(filtFs) & file.exists(filtRs)
filtFs <- filtFs[exists]
filtRs <- filtRs[exists]
sample.names <- sample.names[exists]

derepFs <- derepFastq(filtFs, verbose = TRUE)
derepRs <- derepFastq(filtRs, verbose = TRUE)
names(derepFs) <- sample.names
names(derepRs) <- sample.names

Deberías ver para cada muestra: cuantas lecturas únicas quedaron. Un ratio alto de secuencias únicas / total puede indicar alta diversidad o contaminación; un ratio muy bajo es normal en muestras con taxones dominantes.

Código 
# Diagnóstico rápido de la primera muestra
n_unique_F     <- length(derepFs[[1]]$uniques)
total_reads_F  <- sum(derepFs[[1]]$uniques)
compression_ratio <- round(n_unique_F / total_reads_F * 100, 2)

message("Secuencias únicas Forward: ", n_unique_F)
message("Ratio de compresión: ", compression_ratio, "%")
message("Top 5 abundancias: ", paste(head(sort(derepFs[[1]]$uniques, decreasing = TRUE), 5), collapse = ", "))

if (compression_ratio < 1)
  message("INFO: Baja diversidad (< 1% únicas). Normal en muestras con especies dominantes.")
if (compression_ratio > 50)
  warning("Alta diversidad inusual (> 50% únicas). Revisa calidad del filtrado o contaminación.")

El pipeline guarda las estadísticas de dereplicación para todas las muestras en final_data/logs/:

Código 
derep_stats <- data.frame(
  Sample        = sample.names,
  Unique_seqs_F = sapply(derepFs, function(x) length(x$uniques)),
  Total_reads_F = sapply(derepFs, function(x) sum(x$uniques)),
  Unique_seqs_R = sapply(derepRs, function(x) length(x$uniques)),
  Total_reads_R = sapply(derepRs, function(x) sum(x$uniques))
)
derep_stats$Compression_ratio_F <- with(derep_stats,
  round(Unique_seqs_F / Total_reads_F * 100, 2))
derep_stats$Compression_ratio_R <- with(derep_stats,
  round(Unique_seqs_R / Total_reads_R * 100, 2))

write.csv(derep_stats,
  file.path(output_location, "logs",
            paste0(run_name, "_", primer.data$locus_shorthand[i], "_derep_stats.csv")),
  row.names = FALSE)

Paso 2 — Aprender el modelo de error

La secuenciadora Illumina comete errores al leer las bases (una A real puede leerse como C, G o T). learnErrors() estima estas tasas para cada tipo de transicion (A->C, A->G, etc.) en función de la calidad Phred de cada posición.

El pipeline primero verifica que haya suficientes datos para estimar el modelo:

Código 
nbases_target <- 1e8   # 100 millones de bases (aumentar si tienes > 50 muestras)
max_consist   <- 25    # más iteraciones que el default (10) para forzar convergencia

# Validar datos disponibles
total_bases_F <- sum(sapply(filtFs, function(f) if (file.exists(f)) file.info(f)$size else 0))
total_bases_R <- sum(sapply(filtRs, function(r) if (file.exists(r)) file.info(r)$size else 0))
message("Forward disponible: ~", round(total_bases_F / 1e6, 1), " MB")
message("Reverse disponible: ~", round(total_bases_R / 1e6, 1), " MB")

if (total_bases_F < 1e6 || total_bases_R < 1e6)
  warning("Datos muy limitados (< 1 MB). El modelo puede ser inestable.")

Los parámetros clave son:

Parámetro Valor Qué hace
nbases 1e8 (100M) Número de bases a usar para aprender el modelo. DADA2 toma tantas muestras como necesite para alcanzar ese total. Aumentar a 2e8 si tienes > 50 muestras
randomize TRUE Selecciona lecturas al azar en lugar de tomar siempre las primeras. Produce un modelo más representativo
multithread TRUE Usa todos los núcleos disponibles del servidor para acelerar el cálculo
MAX_CONSIST 25 Número máximo de iteraciones del algoritmo. El default de DADA2 es 10; aquí se aumenta a 25 para garantizar convergencia
Código 
errF <- tryCatch({
  learnErrors(filtFs, nbases = nbases_target, randomize = TRUE,
              multithread = TRUE, MAX_CONSIST = max_consist, verbose = TRUE)
}, error = function(e) {
  stop("Error al aprender modelo Forward: ", conditionMessage(e))
})

errR <- tryCatch({
  learnErrors(filtRs, nbases = nbases_target, randomize = TRUE,
              multithread = TRUE, MAX_CONSIST = max_consist, verbose = TRUE)
}, error = function(e) {
  stop("Error al aprender modelo Reverse: ", conditionMessage(e))
})

Este paso puede tardar varios minutos. La salida indica cuántas bases y muestras se usaron, y cuántas rondas necesitó el algoritmo para converger. Por ejemplo:

103156235 total bases in 1587019 reads from 12 samples will be used for learning the error rates.
Initializing error rates to maximum possible estimate.
selfConsist step 1 ............
   selfConsist step 2
   ...
Convergence after 10 rounds.

¿Qué significa “convergencia”?

learnErrors() trabaja de forma iterativa: en cada ronda estima las tasas de error → infiere ASVs con esas tasas → re-estima los errores con las ASVs inferidas. Cuando las estimaciones dejan de cambiar entre rondas, el modelo convergió. Convergencia en menos de 10 rondas es ideal; si no converge en 25 hay un problema con los datos o los parámetros.

Tip

Resultado esperado: convergencia en 5–15 rondas para Forward y Reverse. Es normal que Reverse necesite una o dos rondas más que Forward, ya que sus lecturas tienen mayor tasa de error.

Después de aprender los modelos, el pipeline los valida automáticamente:

Código 
# Validar modelo Forward
# err_out: matriz 16×41 — filas = transiciones (A2A, A2C, …), columnas = Q-scores (0–40)
# Las transiciones correctas (A2A, C2C, G2G, T2T) tienen probabilidad ≈ 1.0 → excluir.
# Las tasas altas en Q<20 son normales (bases de baja calidad son intrínsecamente inciertas).
# Solo se evalúa Q≥20, donde vive la mayoría de las lecturas filtradas.
if (!is.null(errF$err_out)) {
  rn         <- rownames(errF$err_out)
  error_rows <- rn[substr(rn, 1, 1) != substr(rn, 3, 3)]   # A2C, A2G, etc.
  q_cols     <- as.integer(colnames(errF$err_out))
  hq_cols    <- which(q_cols >= 20)                          # columnas Q≥20

  err_hq  <- errF$err_out[error_rows, hq_cols, drop = FALSE]
  max_err <- max(err_hq, na.rm = TRUE)

  message("Tipos de transición de error: ", length(error_rows), " (de 16 posibles)")
  message("Tasa de error máxima en Q≥20: ", round(max_err, 5),
          " (normal si < 0.05; preocupante si > 0.10)")

  if (max_err > 0.1)
    warning("Tasa de error > 10% en Q≥20. Revisa el perfil de calidad del run.")
  else
    message("Modelo de error OK.")
}

Paso 3 — Visualizar el modelo de error

El gráfico de errores muestra las 12 posibles transiciones (A->C, A->G, etc.). Los puntos rojos son las tasas observadas; la linea negra es el modelo ajustado. Deben seguir el mismo patrón: la tasa de error cae conforme aumenta la calidad (Q-score).

Código 
plotErrors(errF, nominalQ = TRUE)
plotErrors(errR, nominalQ = TRUE)

El pipeline guarda estas gráficas automáticamente en final_data/logs/:

Código 
png(file.path(output_location, "logs",
              paste0(run_name, "_", primer.data$locus_shorthand[i], "_errF.png")),
    width = 1200, height = 1200, res = 150)
print(plotErrors(errF, nominalQ = TRUE))
dev.off()

png(file.path(output_location, "logs",
              paste0(run_name, "_", primer.data$locus_shorthand[i], "_errR.png")),
    width = 1200, height = 1200, res = 150)
print(plotErrors(errR, nominalQ = TRUE))
dev.off()

¿Que buscar en el gráfico?

Senal Interpretación
Puntos grises cerca de la linea negra Buen ajuste del modelo [OK]
Puntos muy dispersos Datos insuficientes o calidad variable en ese bin de Q
Tasas de error > 10% en Q≥20 (A->C, etc.) Posible problema de calidad del run
Transiciones correctas (A->A, C->C…) altas y planas Normal — no son errores

Los tres elementos del gráfico

La gráfica tiene 16 paneles — uno por cada posible transición entre bases (4 bases × 4 posibles lecturas). Se organizan en una cuadrícula de 4×4:

  • Diagonal (A2A, C2C, G2G, T2T): lectura correcta — la base real y la leída son la misma. La probabilidad es alta (cerca de 1.0) y se mantiene plana conforme sube el Q-score. Estos paneles no representan errores; son la referencia de que el modelo funciona.

  • Fuera de la diagonal (A2C, A2G, C2A, T2G, etc.): errores reales — la secuenciadora leyó una base distinta a la real. La tasa debe bajar conforme sube el Q-score (eje X): a mayor calidad Phred, menos errores de ese tipo.

Cada panel tiene tres elementos:

Elemento Qué representa
Puntos grises Tasas de error observadas en tus datos, agrupadas por Q-score
Línea negra Modelo ajustado por DADA2 — lo que aprendió learnErrors()
Línea roja Tasa teórica según la definición nominal del Q-score (Q20 = 1 error/100 bases, Q30 = 1/1000, etc.)

La línea negra no tiene que coincidir con la línea roja: la roja asume un modelo ideal de Illumina, pero cada run tiene su propio perfil de error real. Lo que importa es que la línea negra siga los puntos grises.

Tip

Ondulaciones en la línea negra en calidades intermedias (Q15–Q25) son normales cuando hay pocos reads en esos bins. No indican un problema si el patrón general sigue siendo decreciente.

Paso 4 — Guardar checkpoint después de learnErrors

El pipeline guarda automáticamente un checkpoint .RData después de learnErrors(). Si el script se interrumpe más adelante, puedes retomar desde aquí sin repetir el paso más lento.

Código 
save(errF, errR, derepFs, derepRs, filtFs, filtRs, sample.names, primer.data, run_name, out,
     file = file.path(output_location, "rdata_output",
                      paste0(run_name, "_", primer.data$locus_shorthand[i],
                             "_checkpoint2_learnErrors.RData")))
message("Checkpoint 2 guardado (learnErrors)")

Para reanudar desde este punto en otra sesión:

Código 
load(file.path(output_location, "rdata_output",
               paste0(run_name, "_", primer.data$locus_shorthand[i], "_checkpoint2_learnErrors.RData")))

Paso 5 — Inferencia de ASVs con dada()

Con el modelo de error aprendido, dada() infiere las secuencias biológicas reales (ASVs) corrigiendo los errores de secuenciación muestra por muestra.

Código 
dadaFs <- dada(derepFs, err = errF, multithread = TRUE)
dadaRs <- dada(derepRs, err = errR, multithread = TRUE)

Al finalizar verás el número de ASVs inferidas por muestra, por ejemplo: Sample 1: 1979 reads in 232 unique sequences, 8 sample sequences, 1.2e+04 input unique sequences.

Código 
# Cuantos ASVs se infirieron en la primera muestra
dadaFs[[1]]

Deberías ver el número de secuencias de muestra (ASVs) vs secuencias únicas de entrada. El ratio refleja cuanto “colapso” el denoising.

Paso 6 — Guardar checkpoint después de dada()

Código 
save(dadaFs, dadaRs, derepFs, derepRs, errF, errR, sample.names, primer.data, run_name, out,
     file = file.path(output_location, "rdata_output",
                      paste0(run_name, "_", primer.data$locus_shorthand[i],
                             "_checkpoint3_dada.RData")))
message("Checkpoint 3 guardado (dada)")

Para reanudar desde este punto antes de mergePairs():

Código 
load(file.path(output_location, "rdata_output",
               paste0(run_name, "_", primer.data$locus_shorthand[i], "_checkpoint3_dada.RData")))

Retención esperada en este paso

Paso Lectura típica
Lecturas únicas tras dereplicación 5-30% del total (normal)
ASVs inferidos vs únicos entrada 1-10% (alta compresión es buena senal)
NotaRecuerda
  • learnErrors() necesita suficientes datos (al menos varios MB de FASTQ filtrados) para estimar tasas confiables.
  • Si el modelo no converge, aumenta MAX_CONSIST a 50 o nbases_target a 2e8.
  • Los modelos errF y errR son independientes: las lecturas Reverse suelen tener tasas de error ligeramente mayores que las Forward, y eso es normal.
TipPara el curso
  1. Revisa plotErrors() - ¿Los puntos grises siguen la linea negra?
  2. Compara el número de ASVs inferidos con el número de secuencias únicas de entrada.
  3. ¿Hay alguna muestra con muy pocos ASVs? ¿Coincide con las que tenian baja retención en filterAndTrim?
